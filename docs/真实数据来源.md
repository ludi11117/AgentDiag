# 真实数据来源调研

> 起因：项目知识库是**合成**的工程故障条目，这是它最大的短板。
> 本文记录"去找真实数据"的实际结果——**包括没找到的**。
>
> 结论先行：**公开渠道找不到可用的真实维修工单**；找到了**真实厂家手册**，
> 但内容与场景**错位**。这不影响项目价值，但必须如实说明。

## 一、找过什么，结果如何

| 来源 | 类型 | 结论 |
|---|---|---|
| 公开"真实维修工单数据集" | 文本工单 | ❌ **不存在**。真实工单是企业内部资产，无公开数据 |
| `alias01/maintenance-work-order-nlp` | 文本工单 | ⚠️ **3000 条但是合成的**，作者 README 明确写 "All text is synthetic" |
| `jvachier/industrial-maintenance-synthetic-data` | 合成生成器 | ⚠️ 合成数据生成器，非真实数据 |
| NASA C-MAPSS | 传感器时序 | ⚠️ 真实，但是**振动/时序信号**，不是"现象→根因"文本 |
| Paderborn 轴承数据集 | 振动信号 | ⚠️ 同上，与 RAG 文本诊断场景不匹配 |
| **西门子官方诊断手册** | **厂家手册 PDF** | ✅ **真实、可下载**，但内容错位（见下） |

### 关键教训

**"真实工单"这类数据在网上搜不到，不是搜索技巧问题。**
它是企业的内部资产，涉及商业机密与客户信息，不会公开发布。
凡是公开的"维修工单数据集"，几乎都是合成的（且大多会如实标注）。

## 二、西门子官方手册：找到了，但错位

### 已验证可下载

| 项 | 内容 |
|---|---|
| 文档 | SINUMERIK 840D/840Di/810D + SIMODRIVE 611digital **诊断手册** |
| 订货号 | `6FC5298-7AA20-3RP3` |
| 版本 | 11/2006 |
| 页数 | 822 |
| 地址 | `https://cache.industry.siemens.com/dl/files/820/34877820/att_68034/v1/DA_1106_cs.pdf` |
| 取回方式 | `curl -sL -o data/raw/siemens_DA_1106_cs.pdf <上面的地址>` |

> 注意：`support.industry.siemens.com` 那个入口会返回 **403**（需登录/JS），
> `cache.industry.siemens.com` 可直接下。实测确认。

### 抽取结果（`tools/parse_manual_pdf.py`）

从 822 页抽出 **1170 条**报警条目：

| 指标 | 数值 | 占比 |
|---|---|---|
| 条目总数 | 1170 | — |
| 有实质「说明」(≥15字) | 589 | 50% |
| 「说明」+「处理」都有 | 490 | 42% |
| 含 `%1`/`%2` 占位符 | 479 | 41% |

代码区间 `100000 ~ 830000`，前缀分布：

| 前缀 | 数量 | 内容 |
|---|---|---|
| `300xxx` | 176 | **SIMODRIVE 驱动报警** ← 与机械/电气故障相关 |
| `101xxx` | 146 | 诊断（系统软件） |
| `100xxx` | 145 | 基本系统 |
| `104xxx` | 129 | 参数 |
| `400xxx` | 88 | PLC 报警 |
| `112xxx`/`105xxx`/`107xxx` | 57/54/54 | 通讯 / 文件 / HMI |

### ⚠️ 为什么说"错位"

抽出来的典型条目长这样：

```
[105061] 打开文件 %1 时出错
   说明: 指定文件不能打开。正常操作情况下不会出现的系统内部错误。
   处理: --
```

```
[109004] 无开关转换：PLC 被高优先级 HMIs 占用
   说明: MMC 正试图切换到被两个具有更高优先权的 MMC 占用的 NCU 中。
   处理: 将两个具有更高优先权的 MMC 中的一个转换到 NCU。
```

**这些是 CNC 系统的软件/通讯/文件报警，不是设备机械故障。**
822 页里与"工业设备故障诊断"真正相关的**只有 `300xxx` + `400xxx` 约 264 条**，
其余 900 多条是"系统内部错误""文件打不开""HMI 通讯"。

而且手册的「处理」字段大量是 `--`（让"通知服务部门"）——
**它是报警代码说明手册，不是维修指导书。**

### 与现有合成库的对比

| | 合成库（现状） | 西门子真手册 |
|---|---|---|
| 真实性 | ❌ 合成 | ✅ 官方权威 |
| 设备类型 | **12 类**通用设备 | **1 类**（Siemens 840D + 611 驱动） |
| 代码格式 | `E-203`（字母-数字） | `300500`（6 位数字） |
| 内容性质 | 现象 → 原因 → 措施 | 报警代码 → 释义 → 处理 |
| 与场景契合度 | 高（但是假的） | **低**（真的但错位） |

**这正是"分水岭"的具体形态：真实度高的东西，恰好不匹配场景。**

## 三、建议方案：双轨，而不是全量替换

### 为什么不全量替换

全换成真手册后，系统**只能诊断西门子数控系统**——
"覆盖 12 类工业设备"这个明确的设计目标直接消失，
30 条用例、29 条备件价格表、11 组设备同义词全部作废。

拿"真实度"换掉"覆盖面"，是净损失。

### 推荐做法

1. **保留合成库作为「业务场景层」**，但在 README 与文档里**如实标明是合成的**
2. **新增「权威手册层」**，只收录 `300xxx`（SIMODRIVE 驱动报警）等与故障诊断相关的条目
3. 两层在文档里**各自说明用途**：一层覆盖多设备与流程验证，一层提供真实报警代码

### 面试口径（可直接用）

> "知识库分两层。一层是合成的业务场景数据，用来覆盖多设备类型、验证完整流程；
> 另一层是从西门子官方诊断手册（订货号 `6FC5298-7AA20-3RP3`，822 页）抽出来的
> 真实报警代码，共 1170 条，其中 490 条说明了+处理齐全。
> 我**不假装合成数据是真实工单**——它们解决的是不同问题。
> 我也验证过全量替换成手册，结论是**不划算**：真实度上去了，
> 但设备覆盖从 12 类掉到 1 类，属于净损失。"

## 四、⚠️ 版权红线（必须遵守）

西门子手册**受版权保护**。因此：

- ✅ `data/raw/` **已加入 `.gitignore`**（`.gitignore:64`），
  手册 PDF **不会**随仓库分发，也不会被误提交
- ✅ 本仓库**不包含**手册抽取出的原文内容
- ✅ 复现方式写在文档里（给下载地址），由使用者**自行下载**
- ❌ **禁止**把手册原文批量提交到公开仓库
- ⚠️ 若确需引用，只保留**报警代码 + 极简释义**（事实性信息），
  并在 README 标注出处与版权归属

> 这条和项目里"`AgentDiag-代码全解.html` 不进公开仓库"是同一类原则：
> **不属于项目产物、或不该公开的内容，先问再动，宁可不提交。**

## 五、复现命令

```bash
# 1. 取回手册（版权归西门子，勿入库）
mkdir -p data/raw
curl -sL -o data/raw/siemens_DA_1106_cs.pdf \
  "https://cache.industry.siemens.com/dl/files/820/34877820/att_68034/v1/DA_1106_cs.pdf"

# 2. 抽取与统计（需要 pypdf）
venv/Scripts/python.exe tools/parse_manual_pdf.py
venv/Scripts/python.exe tools/parse_manual_pdf.py --dump 20    # 看明细
venv/Scripts/python.exe tools/parse_manual_pdf.py --json       # 导出报告
```

> `pypdf` 已装（6.19.0）。解析时会打印 `fontTools is required...` 警告，
> 属正常现象（该 PDF 用了 Type1 字体），不影响中文正文抽取。
