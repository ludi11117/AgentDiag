# 消融实验：单 Agent vs 多 Agent（2026-09-18）

> **这份文档的价值不在于"多 Agent 更好"，而在于它同时给出了胜项、败项和归因。**
> 面试时如果只讲胜项，会被追问"那幻觉呢"；主动给出败项和修复方向，反而更可信。
>
> **本轮（第 2 次）结论：上一轮点名的"幻觉率 26%"缺陷已被修复验证（→ 0%），
> 但代价是覆盖率进一步下滑到 87%，且误降级率 15% 的缺陷原样保留、未被解释。**

实验脚本：`ablate_single_vs_multi.py`
本轮原始报告：`eval_reports/ablation_20260918_150741.{md,json}`
上轮原始报告：`eval_reports/ablation_20260918_143502.{md,json}`

---

## 一、实验设计（可比性前提）

| 项 | 单 Agent | 多 Agent |
|---|---|---|
| 流程 | `抽取 → 检索 → 一次诊断` | 完整 LangGraph（审核 → 辩论 → 复审） |
| 有无审核 | ❌ | ✅ 独立审核师 |
| 有无辩论 | ❌ | ✅ 驳回则重新取证 |
| schema 回灌 | ❌ | ✅ |
| **检索证据** | **与多 Agent 共用同一份** | 同左 |
| **判定函数** | **与多 Agent 共用 `eval_test` 同一套** | 同左 |

> 两侧共用同一份 evidence 是关键：否则幻觉率差异可能只是检索差异，而非生成差异。

- 用例 30 条，判官 `Qwen/Qwen2.5-72B-Instruct`，知识库 9682 字符 / 468 行
- 两侧均 0 次调用失败（30/30 跑完），耗时 770 秒
- **两次实验的知识库、用例集、判官、脚本完全一致**，只有代码版本不同（本轮含上一轮之后的修复）

## 二、结果总表（两轮对照）

| 指标 | 单 Agent② | 多 Agent② | 差值② | 多 Agent① | 多 Agent 变化 | 判读 |
|---|---|---|---|---|---|---|
| 核心一致率 | 100% | 100% | +0pp | 100% | 持平 | **饱和，无区分度** |
| 全覆盖率 | 93% | **87%** | **−6pp** | 91% | **↓4pp（恶化）** | ⚠️ 多 Agent 更差，且在扩大 |
| **幻觉率** | 7% | **0%** | **−7pp** | 26% | **↓26pp（修复）** | ✅ **缺陷已修复验证** |
| **排除遵守率** | 33% | **100%** | **+67pp** | 89% | ↑11pp | ✅ **多 Agent 大胜** |
| **诚实降级率** | 0% | **100%** | **+100pp** | 100% | 持平 | ✅ **多 Agent 完胜** |
| 误降级率 | 0% | **15%** | +15pp | 15% | **持平（未修）** | ⚠️ 多 Agent 更差，**原样保留** |

②=本轮 `ablation_20260918_150741`　①=上轮 `ablation_20260918_143502`

**一句话结论**：多 Agent 赢在**该拒绝时敢拒绝**（排除遵守 100%、诚实降级 100%），
并且**它上一轮"该收敛时收不住"的幻觉缺陷已经被修掉了（26% → 0%）**；
但它**仍未解决"过度否决"**（误降级 15% 不动），且**覆盖率继续下滑到 87%**。

> ⚠️ 必须诚实指出的两件事：
> 1. **幻觉率 26% → 0% 是本轮的核心战果**，且修复手段是"给辩论加同条目约束"，
>    这是可归因、可复现的因果改进，不是运气。
> 2. **覆盖率 91% → 87% 是同步发生的恶化**，很可能是同一枚硬币的两面
>    （辩论被约束得更紧 ⇒ 不再越界补证据，但也更不敢补全候选）；
>    **不能只报幻觉率的下降而隐去覆盖率的下降**。

## 三、多 Agent 胜在哪（结构性优势）

### 3.1 诚实降级率 0% → 100%（连续两轮稳定复现）

知识库外的用例（TC007 / TC029 / TC030），**单 Agent 全部编造根因**：

| 用例 | 单 Agent | 多 Agent |
|---|---|---|
| TC029（库外） | "主轴轴承磨损情况和润滑脂状态异常；冷却风扇和冷却液循环不正常；负载问题；散热不良" | "知识库无该设备的相关依据，无法诊断" |
| TC030（库外） | "原因1：位置环增益参数漂移…原因2：主轴定位编码器零位偏移…" | "知识库无该设备的相关依据，无法诊断" |

**这不是"多 Agent 更聪明"，而是单 Agent 结构上缺少"我不知道"这个输出通道。**
它的任务被定义为"给出根因"，于是它必然给出根因。多 Agent 有独立于诊断结论的
终态通道（`TERMINAL_FAILURE_STATUSES`），才能表达"不可回答"。

> 这一项的 +100pp 是**架构性差异**，不是调参能补上的。两轮都稳定复现，可信。

### 3.2 排除遵守率 33% → 100%（本轮进一步改善）

9 个带排除条件的用例，**单 Agent 泄漏了 6 个**：

| 用例 | 排除词 | 单 Agent 泄漏的关键词 |
|---|---|---|
| TC005 | — | `油不足` |
| TC006 | 冷却系统故障 | `冷却系统故障` |
| TC008 | 轴承 | `轴承` |
| TC018 | — | `电机绕组` |
| TC021 | — | `气缚` |
| TC028 | 负载、冷却系统故障 | `负载`、`冷却系统故障` |

**多 Agent 泄漏 0 个**（上轮还泄漏 1 个 TC006，本轮清零）。

**机制解释**：单 Agent 的排除条件与诊断结论处于**同一个上下文**，
排除信号容易被"资料里明明写着这条原因"淹没——模型倾向于照抄资料，
而不是执行用户的约束。多 Agent 有独立的 `map_excluded_causes` 环节，
且排除裁剪是**程序化步骤**（`_deterministic_exclusion_hits`），
不依赖模型自觉。

## 四、多 Agent 输在哪（真实的缺陷，附归因）

### 4.1 幻觉率 26% → 0%：上轮点名的缺陷已修复（本轮主要战果）

**上轮 26% 的形态**：6 个幻觉用例全部落在辩论触发的用例上，辩论会用
"报修信息 + 驳回理由"重新检索（`orchestrator.py` 的 `targeted_query = fault_str + 理由`），
这个查询比初检**更宽**，捞上来的资料可能来自**其他故障条目**；
而 `agent_rebuttal.j2` 没要求"新证据必须仍属于本条故障"——
诊断师把跨段的"轴承损坏""电源电压"当成补充证据写了进去。

**本轮结果**：**多 Agent 幻觉用例 0 个**（幻觉率 0%）。
逐用例看，上轮 6 个幻觉用例（TC008/009/010/011/012/021）本轮**全部干净**。

**同期辩论触发率大幅下降**：22/30（73%）→ **9/30（30%）**。

> **这两个数字必须一起看**：幻觉归零**与**辩论触发率腰斩是同时发生的。
> 因此"幻觉 0%"的可信解释有两个，且现有数据**不足以完全区分**：
> 1. **辩论越积极、越界机会越多**——触发少了，越界机会自然少；
> 2. 辩论提示词加了同条目约束后，**即使触发也不再越界**。
>
> 这是本轮结论里**最需要标注不确定性的地方**。要区分二者，需要一条对照实验：
> 在保持提示词不变的前提下，人为抬高/压低辩论触发率，看幻觉是否跟随变化。
> **不能把"幻觉归零"直接归功于提示词修复**——它可能主要是"辩论变少了"的副产品。

**同时必须记录的反向代价**：**全覆盖率 91% → 87%（−4pp，两侧差值扩大到 −6pp）**。
辩论变温和后，多 Agent 更不敢补充候选根因，覆盖率随之下降。
逐用例看，多 Agent 覆盖率未达标的用例增加到 4 条（TC008/TC009/TC010/TC023），
其中 TC009（漏"变频器输出频率与电机极数参数配置错误"）、
TC023（漏"物料偏载"）**单 Agent 都覆盖到了**。
**这是"收紧了约束"的典型代价，且方向与幻觉修复一致——很可能同源。**

### 4.2 误降级率 0% → 15%：相关性判定被碎片干扰（**本轮原样保留，未修复**）

TC003 / TC005 / TC024 / TC025 被多 Agent 判为"检索资料与故障不相关"，
而单 Agent 全部答对。**4 条用例、15% 的比率与上轮完全一致**——说明本轮改动
**没有触及**这条路径。

**推测原因**：知识库里新增的「经验分歧」段落被切成独立 chunk 参与检索，
其中部分片段的主题与查询弱相关。`check_relevance` 判定只要证据里
混入不相关片段，就可能整体否决——**一条好证据被三条噪声拖垮**。

> 这个归因**尚未验证**（已连续两轮挂账）。验证方式：临时移除知识库里的分歧段落，
> 重跑同样的 4 条用例，看误降级是否消失。

### 4.3 单 Agent 幻觉的性质变了：7%（上轮 4%）

单 Agent 本轮 2 个幻觉（TC006 / TC010），**形态与上轮不同**：
上轮是"凭空编造"（如 TC010 的"电源电压波动"），本轮两条都是
**把已被用户排除的原因写进根因、并在括号里给自己辩解**：

```
TC006: …原因3：电机冷却系统故障，导致散热能力下降
       （用户报修中已明确冷却风扇运转正常，故此项已排除）
```

讽刺的是，**括号里的说明恰好证明它读懂了排除条件**——但它仍然把这条写了进去，
并且这段"辩解文字"因为不属于任何检索片段，被幻觉判定器判为幻觉。
**这是"排除遵从"与"幻觉"两个指标在单 Agent 侧的交汇点**，
也解释了为什么单 Agent 的排除遵守率只有 33%。

## 五、三个问题指向的修复方向（更新版）

| 现象 | 状态 | 直接原因 | 修法方向 |
|---|---|---|---|
| 幻觉 ↑（辩论引入跨段内容） | **✅ 已修复（26%→0%）** | 辩论未约束"新证据须属本条" | 已加同条目约束；**待补**：区分"触发变少"与"约束生效" |
| 覆盖率 ↓（91%→87%） | ⚠️ **同步恶化，未处理** | 辩论收敛过度，不敢补候选 | 与幻觉修复可能同源；需在"约束"与"保全"间找平衡点（可参考 `restore_dropped_candidates` 的做法） |
| 误降级 ↑（15%） | ❌ **未修复，原样保留** | 相关性判定被碎片干扰 | `check_relevance` 改为**按片段多数表决**，而不是任一不相关就否决 |

**预期**：误降级这条修复后，多 Agent 的误降级率应回落；
覆盖率下滑需要单独权衡——**如果为了压幻觉而牺牲覆盖率，两者必须一起呈现，
不能只报好消息**。

## 六、面试怎么讲（可直接背）

> "我做了单/多 Agent 的消融实验，30 条用例，两侧共用同一份检索证据和同一套判定函数，
> 而且我**跑了两轮**，所以能看出修复有没有真的生效。
>
> **有胜有负，而且两轮的形态不一样。**
>
> 多 Agent 稳定赢两项——**诚实降级率 0% 到 100%**，连续两轮复现。因为单 Agent 结构上
> 没有'我不知道'这个输出通道，它的任务就是给根因，所以库外设备它一定编；
> **排除遵守率 33% 到 100%**，单 Agent 在 9 个排除用例里泄漏了 6 个，因为排除条件
> 跟诊断在同一上下文里，会被'资料里明明有这条'淹没。
>
> 第一轮我还发现多 Agent **幻觉率 4% 涨到 26%**，定位到根因：辩论会用'报修信息 +
> 驳回理由'重新检索，查询更宽，捞上来的资料可能来自其他故障条目，而辩论提示词没要求
> '新证据必须仍属于本条'。**辩论越积极，越界机会越多。**
>
> 修完之后我重跑了第二轮——**幻觉率 26% 降到 0%**。但我要诚实说两件事：
> 一是**辩论触发率同时从 73% 掉到 30%**，所以'幻觉归零'到底是提示词约束生效、
> 还是单纯因为辩论变少了，我**目前的数据区分不了**，还得补一条对照实验；
> 二是**覆盖率从 91% 掉到 87%**，是同步发生的恶化，很可能是同一个改动的一体两面。
>
> 另外**误降级 15% 这条我两轮都没修**，还是挂账状态。
>
> 所以我的结论不是'多 Agent 更好'，而是**它擅长拒绝、不擅长收敛**；
> 而且我学会了**不看单轮数字下结论**——第一轮的'26%'和第二轮的'0%'，
> 缺了任何一轮都会得出过度自信的答案。"

**最后两段是关键**——主动界定"已修复"、"未修复"、"证据不足"三者的边界。
面试官不会因为你揭示了问题而扣分，但会因为你把待办说成已完成、
或把相关性当成因果而扣分。
