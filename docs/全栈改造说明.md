# 全栈改造说明（React + FastAPI 前后端分离）

> 记于 2026-09-18。本次改动把前端从"Streamlit 直连业务模块"改为真正的前后端分离，
> 并顺带修掉了一个与本次改动直接相关的 P1 缺陷。

## 一、为什么改：原来的架构有个说不通的地方

改造前的真实数据流：

```
Streamlit app.py ──import──> orchestrator / agents
       │
       └── (x)  api.py 那 344 行从未被前端用过
```

`app.py` 直接 `import orchestrator.run_diagnosis`，**绕过了 `api.py`**。
接口层是给外部调用者准备的，但自己的前端没走。这在架构上不成立：
要么承认没有接口层，要么让前端走它。

这个叙事值得在面试里讲：**不是"嫌 Streamlit 不好看所以换 React"，
而是"我审计了自己的架构，发现前端旁路了接口层，把它补齐了"。**
前者是审美偏好，后者是工程判断。

改造后：

```
React (5173/8080) ──HTTP/SSE──> FastAPI ──> orchestrator / agents
                                     ↑
                              唯一入口，可独立测试与部署
```

## 二、新增的技术点（每条都能被追问）

### 1. SSE 流式推送（`POST /diagnose/stream`）

一次诊断要串行走 6~9 次 LLM 调用、耗时数十秒。改造前只能等全部跑完才返回，
用户在几十秒里看不到任何进展。

现在复用 `orchestrator.run_diagnosis_stream()` 生成器（**不重复业务逻辑**），
每个节点推一条 `progress` 事件，最后推 `result` + `done`。

**三个容易踩的坑，都已处理并写了测试：**

| 坑 | 后果 | 处理 |
|---|---|---|
| 不共用并发闸门 | SSE 成为绕开限流的后门，配额被打爆 | 共用同一把 `BoundedSemaphore` |
| 闸门在端点内 finally 释放 | 端点 early return 时诊断还没开始跑，闸门泄漏 | 在**生成器**的 finally 里释放 |
| 不关反代缓冲 | 逐节点进度退化成"最后一次性全出来"，SSE 白做 | `X-Accel-Buffering: no` + nginx `proxy_buffering off` |

### 2. 前端手写 SSE 解析（不用 EventSource）

`EventSource` 有三个致命限制：

1. **只支持 GET** —— 端点是 POST（故障描述可能很长，还带 base64 图片，
   塞进 URL 不现实且会撞代理的 URL 长度限制）；
2. **无法自定义请求头** —— 带不了 `X-API-Key`，后端开鉴权就用不了；
3. **断线自动重连** —— 对"重连就重跑一遍、每次烧 6~9 次 LLM 调用"的场景，
   自动重连是**有害的**。

所以用 `fetch` + `ReadableStream` 手写。最容易踩的坑：
**一个 SSE 消息可能被 TCP 切成多个 chunk，一个 chunk 里也可能含多条消息**，
必须在循环外累积 buffer、以空行分隔，不能按 chunk 直接解析。

### 3. 类型契约手写对齐

`web/src/types/contracts.ts` 里每个类型都标注了「契约来源：agents.py :: XXXOutput」。
不用 `openapi-typescript` 自动生成，原因是后端用中文键名（`根因判断` / `工单编号`），
自动生成会把键名原样搬过来但**丢掉语义**——看不出哪个字段是"降级时可能整体缺失"的。

### 4. 状态机 + 辩论环可视化

`StateMachineView.tsx` 把 9 个节点画成一条进度链。
改造前只有一行行滚动的文字日志，看不出"走到哪了、还剩几步、辩论环走了没有"。

辩论环（审核 ⇄ 反驳 ⇄ 复审）单独高亮——它是多 Agent 架构的核心，
也是"单 Agent 做不到"的论据所在。

### 5. 图表执行兜底（顺带修的 P1）

**问题本质是"兜底放错了层级"**：`workorder_node` 内部那段"工单生成失败"兜底，
只覆盖"走到了 workorder 但 LLM 挂了"。异常若发生在更早的节点（retrieve / diagnose /
rebuttal），图**到不了** workorder，异常直接冒到 `run_diagnosis` 的 `except` 被 raise 出去。

后果：用户烧掉几十次 LLM 调用、等了十几分钟，最终拿到 **0 交付物**——
而项目对外宣称的核心保证是"任何失败都产出带风险标记的工单，没有死胡同"。

修复：把兜底挪到最外层调用点（`build_abort_workorder()` / `build_abort_result()`）。

- `run_diagnosis`：except 分支改为 **return** 降级结果
- `run_diagnosis_stream`：except 分支改为 **yield** 降级终态 ——
  前端才能以"降级完成 + 待人工处理工单"收场，而不是"连接断开"
- 兜底工单**只含三项**（工单编号 / 风险等级 / 风险说明），
  不补空章节——没有依据的"维修方案"比没有更危险

**为什么这件事必须排在 SSE 之前做**：SSE 会把每个节点状态实时推给前端，
如果图在中间挂了而兜底没补上，前端会永远卡在"正在辩论"上，观感比原先更差。

### 6. recursion_limit 显式收口

此前全项目零配置，用 LangGraph 默认值 **10007**——最坏情况能执行上万次节点、
成倍烧掉配额才报错。新增 `GRAPH_RECURSION_LIMIT`（默认 100），
`invoke` / `stream` 均显式传入。

## 三、验证证据

| 项 | 结果 |
|---|---|
| 后端测试 | **263 项通过**（227 原有 + 35 新增 + 1） |
| 前端类型检查 | `tsc --noEmit` 无错误 |
| 前端构建 | 成功，162 KB / gzip 53 KB |
| 退化验证四步 | 断开接线→红 5 项；流式挪回 raise→红 2 项；删 cost 占位→红 1 项；绕过闸门→红 5 项；还原→全绿 |
| 端到端 | React(5173) → Vite 代理 → FastAPI(8000) → SSE，**12 个事件在 3.61s 内以 0.4s 间隔分批到达** |

最后一项的"**分批到达**"是关键证据：如果所有事件在同一毫秒到达，说明被缓冲了，
SSE 就没生效。`tools/smoke_sse.py` 专门检查这一点。

## 四、新增的 SSE 契约的一个细节

`result` 事件额外带 `record_id` 字段（`api.py` 在落库后回填）。
前端据此直接拼出工单下载地址 `/records/{id}/workorder.md`，
不必让用户跑到历史页去翻自己刚做完的这一次。

为此 `database.save_diagnosis_record()` 改为返回 `lastrowid`
（必须在同一个连接作用域内取，出了 `with` 块游标就失效了）。

## 五、启动方式

```bash
# 方式一：三个脚本各开一个终端
启动后端.bat          # FastAPI  → 8000
启动React前端.bat     # React    → 5173
启动前端.bat          # Streamlit → 8501（历史页 / 统计页）

# 方式二：Docker
docker compose up -d  # 前端 8080，后端 8000，Streamlit 8501
```

开发期 Vite 把 `/api/*` 代理到 `127.0.0.1:8000`，**不需要配 CORS**；
生产期 nginx 承担同样的角色（`web/nginx.conf`）。
前端代码里所有请求都写 `/api` 前缀，不出现后端主机名——
**两种环境下请求路径完全一致，不需要判断环境。**

## 六、本次没做的事（如实说明）

- **历史页与统计页仍由 Streamlit 提供**。接口（`/records`、`/stats`）已就绪，
  迁移是纯前端工作。之所以不一次全迁，是不想让回归面一次铺太大。
- **前端无单元测试**。SSE 解析与状态归约是纯函数，适合补测试；
  当前依赖后端侧的 `tests/test_graph_abort_and_sse.py` 覆盖接口契约。
- **移动端只做了基础响应式**，未针对触屏优化。
- **新基线尚未推送到远端**（与远端历史无共同祖先，需先决定 push 策略）。

## 七、面试可讲的三句话

1. **架构自查**：我发现自己的前端绕过了接口层，`api.py` 形同虚设——把它补齐了。
2. **流式的三个坑**：共用闸门（否则成后门）、生成器内释放（否则泄漏）、
   关缓冲（否则退化成非流式）——每个都有测试守着。
3. **先修兜底再上流式**：因为流式会把"图挂了不给交付物"这个缺陷
   从"少交付"放大成"连接挂死"，所以顺序不能反。
